# Анализ: категории, диапазоны цен и точная цена в CleverPos

## Почему возникла путаница «категория 12800–15000»

В исходном `items.txt` у вас был **не каталог товаров**, а **прайс-правила владельца**:

```
Бомбер/накидка от 12800 до 15000
```

Это значит: *«накладки в магазине обычно продаём в этом коридоре цен»*.

В первой версии файлов это ошибочно оформили как **CAT-05 с числами в названии**. Числа **12800–15000 — не категория**, а **допустимый коридор цены** для типа «Бомбер/накидка».

**Категория** в CleverPos — это:

| Уровень | Поле | Пример |
|---------|------|--------|
| Семейство | `Family` | Женское |
| Подсемейство | `SubFamily` | Накидки |
| Товар | `Designation` | Накидка *(только тип, без цвета)* |
| **Цена в чеке** | `Price1` | **15000** (верх коридора «до», **уже с НДС 12%**) |

Покупатель в чеке видит **название товара** и **одну сумму**, не диапазон.

---

## Как CleverPos берёт цену (без доработок кода)

```
Скан штрихкода / выбор кнопки на кассе
        ↓
Находится fin_article по BarCode или Code
        ↓
В чек попадает Price1 × количество (Price1 **включает НДС**, флаг «Цена с НДС» в карточке).
```

**Диапазон «от–до» в кассе сам не выбирается.** Нужна **одна зафиксированная цена** на каждый SKU (артикул / штрихкод).

## Три способа работать с вашими диапазонами

### Вариант A — рекомендуемый для вашего магазина

**Один товар (одно фото) = один SKU = одна точная цена `Price1`.**

- Диапазон из `price_tiers.txt` — **подсказка продавцу** при заведении карточки.
- Перед импортом при необходимости правите колонку `Price1` в `articles_import_backoffice.csv`.
- По умолчанию **Price1 = верхняя граница** коридора (колонка «до»).
- Пример: накидка BK-001 — коридор 12 800–15 000, в импорте **15 000 ₸**.

**Плюсы:** понятный чек, скан EAN, без путаницы на кассе.  
**Минусы:** у каждой новой вещи нужно один раз указать цену.

### Вариант B — несколько SKU на один тип (если часто продаёте «дешёвую / среднюю / дорогую» блузку без отдельного фото)

Вместо одной «Блузки с диапазоном» заводите, например:

| Code | Designation | Price1 |
|------|-------------|--------|
| BL-STD | Блуза | 10000 |
| BL-MID | Блуза | 15000 |
| BL-PRM | Блуза | 15000 |

У каждой — свой штрихкод. Кассир сканирует этикетку нужного уровня.

**Плюсы:** цена выбирается сканом, без правки на кассе.  
**Минусы:** больше карточек; нужны этикетки на уровни.

### Вариант C — правка цены на кассе вручную

Теоретически можно менять цену строки при продаже (зависит от прав пользователя и настроек POS). Это **не зафиксировано** в текущем импорте и хуже для учёта.

**Для стабильного магазина лучше вариант A.**

## Связь файлов в папке `shop/`

```
price_tiers.txt          ← 20 правил «тип + коридор цен» (ваш исходный список)
articles_import*.csv     ← конкретные товары с фото + Price1 (ТОЧНАЯ цена)
images/                  ← фото, имя = Code + описание
```

| Файл | Роль |
|------|------|
| `price_tiers.txt` | Справочник **типов** и **мин–макс** (для вас, не для кассы) |
| `PriceTierId` в CSV | Ссылка товара на строку из price_tiers (например T05) |
| `Price1` в CSV | **Точная цена продажи** — попадает в чек |
| `PriceMin` / `PriceMax` в полном CSV | Напоминание коридора; в БД не импортируются |

---

## Что проверить перед импортом

1. Откройте `articles_import_backoffice.csv`.
2. Для каждой строки: цена `Price1` внутри коридора из `price_tiers.txt`? Если нет — исправьте.
3. Если цена ещё не решена — оставьте предложенную (`PriceSuggested` в полном CSV) или поставьте свою.

Колонка **«УТОЧНИТЬ»** в полном CSV — товары, где предложенная цена условная; лучше сверить с ценником на вешалке.

## Ответы на ваши вопросы

| Вопрос | Ответ |
|--------|--------|
| Почему не переименовали фото? | В прошлый раз дали только таблицу; **сейчас все 18 файлов переименованы и лежат в `shop/images/`** |
| Что за «категория 12800–15000»? | Это **ценовой коридор** для типа «Бомбер/накидка», не название категории в кассе |
| Как выбрать точную цену? | По умолчанию **верх коридора («до»)** в `Price1`; при необходимости правите вручную |
| Можно ли оставить диапазон в чеке? | Нет, в чеке всегда одна сумма за позицию |

## Пример: накидка BK-001

| Поле | Значение |
|------|----------|
| Тип (tier) | T05 — Бомбер/накидка |
| Коридор | 12 800 – 15 000 ₸ |
| Price1 (точная) | **15 000 ₸** (максимум коридора) |
| В чеке | `Накидка` × 1 = **15 000 ₸** |

Цвет и модель в название не пишем — завтра другой цвет, название не меняется; различие по штрихкоду/Code. Подробнее: `items.txt`, `README.md`.
